# Типы блоков

Регистрация блоков, иконки, лимиты, категории и модальный пикер.

## Регистрация: `block()`

| Параметр | Тип | Описание |
|-----------|------|----------|
| `$name` | `string` | Ключ `snake_case`, сохраняется в JSON как `_type` |
| `$title` | `string` | Человекочитаемый заголовок (табы, пикер) |
| `$fields` | `iterable` | Поля MoonShine (в т.ч. вложенные `FlexibleLayouts`) |
| `$limit` | `?int` | Максимум инстансов этого типа (по умолчанию — без ограничений) |
| `$category` | `?string` | Группировка в пикере |
| `$description` | `?string` | Короткое описание в карточке пикера |
| `$icon` | `?string` | Имя иконки MoonShine, emoji или SVG-строка |

Базовое использование с лимитом:

```php
->block('cta', 'Призыв к действию', [
    Text::make('Текст кнопки', 'label'),
    Text::make('Ссылка', 'url'),
], limit: 1)
```

### Ошибки регистрации

`block()` валидирует вход и бросает `InvalidArgumentException` при:

- **дубликате имени после нормализации** — имена сравниваются после `squish()->snake()` (например, `'Hero'` и `'hero'` конфликтуют). Молчаливый дубль сделал бы второй блок недостижимым (`findByName()` возвращает первый совпадающий);
- **`limit < 1`** — нулевой или отрицательный лимит означал бы «добавить нельзя никогда»; для неограниченного количества передайте `null`.

```php
->block('hero', 'Hero', [...])
->block('Hero', 'Другой Hero', [...])   // InvalidArgumentException: already registered
->block('cta', 'CTA', [...], 0)         // InvalidArgumentException: limit must be >= 1
```

С категорией, описанием и иконкой (именованные аргументы):

```php
->block('hero', 'Hero', [
    Text::make('Заголовок', 'title'),
    Image::make('Фон', 'image'),
], category: 'Шапка', description: 'Большой баннер с фоном', icon: 'photo')

->block('gallery', 'Галерея', [
    Json::make('Изображения', 'images'),
], category: 'Медиа', description: 'Сетка изображений', icon: 'rectangle-stack')
```

Блоки без категории попадают в группу «без группировки». Если категорий нет ни у одного блока — ряд пилюль категорий скрывается автоматически.

## Иконки

Параметр `icon` принимает три типа значений:

| Тип | Пример | Рендерится как |
|------|---------|----------------|
| Имя иконки MoonShine | `'photo'` | SVG из `moonshine::icons.photo` |
| Emoji | `'📷'` | Как есть |
| Сырой SVG | `'<svg>...</svg>'` | Pass-through HTML |

MoonShine включает **301 Heroicons** (stroke, 24×24). Список — в `vendor/moonshine/moonshine/src/UI/resources/views/icons/`. Часто используемые: `users`, `photo`, `document-text`, `rectangle-stack`, `bars-3`, `cog-6-tooth`, `star`, `bolt`, `globe-alt`, `bookmark`.

Иконка отображается и на табе, и в карточке пикера.

> ⚠️ **Безопасность:** значение `icon` рендерится как HTML (`{!! !!}` / `x-html`) и предназначено только для developer-trusted данных. Никогда не передавайте туда пользовательский ввод.

## Модальный пикер

Клик по «Добавить блок» открывает модал в стиле Gutenberg:

- **Поиск** — фильтрация по заголовку, описанию и имени блока
- **Категории** — пилюли фильтрации (показываются при 2+ категориях)
- **Сетка карточек** — иконка + заголовок + описание; клик добавляет блок

`Esc` или клик вне модала — закрытие.

### z-index / совместимость

Оверлей пикера живёт на слое модалов ядра MoonShine — `z-index: var(--z-modal, 1100)`. Он остаётся ниже меню ядра (`--z-menu: 1200`) и тостов (`--z-toast: 1300`); пакеты с собственными elevated-слоями (например, диалоги `moonshine-media-manager` на 1150/1250) всегда лежат выше. Не поднимайте оверлей выше шкалы ядра — это вернёт исходный баг с `9999`.

## Управление полем

```php
->disableAdd()     // скрыть кнопку «Добавить блок»
->disableRemove()  // скрыть кнопку удаления у блоков
->disableDuplicate()  // скрыть кнопку дублирования у блоков
->disableSort()    // запретить drag-сортировку
```

Кастомные кнопки:

```php
->addButton(ActionButton::make('Добавить')->primary())
->removeButton(ActionButton::make('Удалить')->icon('trash')->error())
->duplicateButton(ActionButton::make('Дублировать')->icon('square-2-stack')->secondary())
```

## Лимиты

При `limit: N` сервер считает инстансы типа по **сохранённой модели** (authoritative) и отклоняет превышение тостом «Limit count N». Для ещё не сохранённых записей (нет модели) используется счётчик из запроса: поле отправляет количество блоков каждого типа своего инстанса (`counts`), вложенные макеты в подсчёт родителя не попадают. Об использовании клиентского счётчика пишется warning в diagnostic-лог. Проверка выполняется в `BlockController::store()` — обход лимита через прямой запрос невозможен. Дублирование блока проходит через тот же эндпоинт — лимит соблюдается и при дублировании.

## DOM-события

Пакет диспатчит события на `document` (bubbles) для интеграции хост-приложения:

| Событие | `detail` | Когда |
|---------|----------|-------|
| `flexible-layouts:block-added` | `{name, column}` | блок добавлен через пикер |
| `flexible-layouts:block-removed` | `{name, column}` | блок удалён |
| `flexible-layouts:block-duplicated` | `{name, column, sourceIndex}` | блок продублирован |

```js
document.addEventListener('flexible-layouts:block-removed', (e) => {
    console.log('удалён блок', e.detail.name);
});
```

## Дублирование блоков

Кнопка дублирования (иконка `square-2-stack`, цвет secondary) рендерится в хедере блока сразу после кнопки удаления. Клик:

1. запрашивает свежий HTML блока того же типа через AJAX (`store()`) — id/name полей уникальны, лимит проверяется сервером;
2. попарно копирует значения полей исходного блока (text/textarea/select/checkbox/radio/hidden, включая вложенные FlexibleLayouts);
3. вставляет блок и таб сразу после исходного и активирует вкладку дубля;
4. диспатчит DOM-событие `flexible-layouts:block-duplicated` с `{name, column, sourceIndex}`.

Файловые поля не копируются (браузерное ограничение) — в дубле они пусты. Кастомизация: `->duplicateButton(...)` / `->disableDuplicate()`.
