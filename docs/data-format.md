# Формат данных

Поле хранит данные как плоский JSON-массив. Каждый элемент содержит ключ `_type` и значения полей блока:

```json
[
  {
    "_type": "hero",
    "title": "Добро пожаловать",
    "image": "hero-bg.jpg"
  },
  {
    "_type": "section",
    "title": "О нас",
    "blocks": [
      {
        "_type": "button",
        "text": "Подробнее",
        "link": "/about"
      }
    ]
  }
]
```

Вложенные `FlexibleLayouts` — это просто вложенные массивы того же формата. Порядок элементов массива = порядок блоков в UI.

## Каст `FlexibleCast`

```php
protected function casts(): array
{
    return [
        'content' => \Povly\FlexibleLayouts\Casts\FlexibleCast::class,
    ];
}
```

- **Чтение:** JSON из БД → массив (`null` при пустом значении или ошибке декодирования).
- **Запись:** массив → JSON (`array_values`, без ключей), `null` при пустом массиве.
- **Лимит глубины:** 64 уровня — защита от рекурсивных DoS-пейлоадов.

## Поведение неизвестных `_type`

Если тип блока удалён из кода, но остался в сохранённом JSON, данные **не теряются**:

| Ситуация | Рендер (`getFilledBlocks`) | Сохранение (`resolveOnApply`) | Колбэки полей (before/after apply) |
|----------|---------------------------|-------------------------------|-------------------------------------|
| Тип зарегистрирован | Блок рендерится | Поля применяются | Выполняются |
| `_type` неизвестен | Пропускается + warning в лог* | Сохраняется verbatim + warning в лог* | Пропускаются |
| Нет `_type` | Пропускается | Отбрасывается | Пропускаются |

\* Только при включённом `config('flexible-layouts.logging')` — см. [Конфигурация](configuration.md).

Такая семантика позволяет безопасно мигрировать набор блоков: удалённые типы продолжают round-trip через save → load, пока вы не перерегистрируете или явно не удалите их из данных. Записи без `_type` считаются повреждёнными и отбрасываются.

Ошибки кодирования/декодирования JSON в касте **всегда** пишутся в лог уровня `error` (независимо от флага logging) — они означают реальную порчу данных.
